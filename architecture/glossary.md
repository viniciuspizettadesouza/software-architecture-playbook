# Architecture Glossary

Use this map for quick recall; follow the links for context and trade-offs.

| Concept | Meaning |
|---|---|
| [ADR](../concepts/adr.md) | A short record of a significant architectural decision and its context. |
| [Artifact Testing](../concepts/artifact-testing.md) | Verify the package, bundle or image that consumers actually receive. |
| [Clean Architecture](../concepts/clean-architecture.md) | Keep policy independent from delivery and infrastructure mechanisms. |
| [Clean Code](../concepts/clean-code.md) | Write code that communicates intent and remains safe to change. |
| [Cohesion](../concepts/cohesion-and-coupling.md) | How strongly the responsibilities inside a module belong together. |
| [Contract-first API](../concepts/contract-first-api.md) | Define and validate an API contract before or alongside its implementation. |
| [Coupling](../concepts/cohesion-and-coupling.md) | The degree to which one module depends on another. |
| [Data Mapper](../concepts/data-mapper.md) | Translate between persistence representation and application/domain models. |
| [Dependency Injection](../concepts/dependency-injection.md) | Supply collaborators from outside the code that uses them. |
| [DIP](../concepts/dependency-inversion.md) | Keep high-level policy from depending directly on low-level details. |
| [DRY](../concepts/dry.md) | Avoid duplicating knowledge that must change together. |
| [Feature-based Architecture](../concepts/feature-based-architecture.md) | Organize code around product capabilities rather than only technical layers. |
| [Fitness Function](../concepts/fitness-functions.md) | An automated or measurable check of an architectural property. |
| [KISS](../concepts/kiss.md) | Prefer the simplest design that adequately solves the problem. |
| [Layered Testing](../concepts/layered-testing.md) | Match test scopes to different failure risks and feedback needs. |
| [Ports and Adapters](../concepts/ports-and-adapters.md) | Isolate external systems behind application-owned boundaries. |
| [Proportional Architecture](../concepts/proportional-architecture.md) | Add architectural structure in proportion to the problem and its risks. |
| [Repository Pattern](../concepts/repository-pattern.md) | Give application code a collection-like boundary for persistence. |
| [Reproducible Results](../concepts/reproducible-results.md) | Preserve enough input and execution context to recreate and verify a result. |
| [Separation of Concerns](../concepts/separation-of-concerns.md) | Separate responsibilities that change for different reasons. |
| [SOLID](../concepts/solid.md) | Five principles for managing responsibility and dependency in OO design. |
| [Trust Boundary](../concepts/trust-boundaries.md) | A point where data or control crosses between different levels of trust. |
| [Twelve-Factor App](../concepts/twelve-factor-app.md) | Practices for deployable, environment-independent services. |
| [YAGNI](../concepts/yagni.md) | Do not build capabilities without a current requirement. |
