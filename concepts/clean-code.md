# Clean Code

## What it means

Code should communicate intent, keep responsibilities focused and make change safe. Names, small cohesive units, explicit contracts and useful tests matter more than a fixed set of formatting rules.

## Why it matters

Most software cost occurs after the first implementation. Readable, local reasoning lowers the cost and risk of later changes.

## When useful

Apply it continuously, while adapting conventions to language, team and product context.

## Don't overdo it

Short is not automatically clear, and extracting every line into a function can make behavior harder to follow. Optimize for understanding, not rule counts.
