# Standards and Formal Methods

## ISO/IEC/IEEE 42010:2022 — Architecture description

Useful for thinking in terms of stakeholders, concerns, viewpoints and architecture descriptions rather than one universal diagram.

Source: [ISO/IEC/IEEE 42010:2022](https://www.iso.org/standard/74393.html). The standard structures architecture descriptions; it does not prescribe one architecture process or notation.

## ATAM — Architecture Tradeoff Analysis Method

Developed by the Software Engineering Institute (SEI). Useful for evaluating architectural decisions against quality-attribute scenarios and exposing sensitivity points, risks and trade-offs.

Source: [SEI ATAM collection](https://www.sei.cmu.edu/library/architecture-tradeoff-analysis-method-collection/). This playbook borrows scenario and trade-off reasoning but does not claim that its lightweight scans are formal ATAM evaluations.

## Reference Architectures

SEI reference-architecture literature is useful to this repository's long-term direction: capturing recurring elements, relationships, vocabulary and patterns for a family of systems while preserving context.

Source: [SEI — Reference Architectures for Big Data Systems](https://www.sei.cmu.edu/blog/reference-architectures-for-big-data-systems/).

## Architecture reconstruction

Useful for recovering an as-built architecture from existing systems rather than assuming that documentation is current.

Source: [SEI — Software Architecture Reconstruction: Practice Needs and Current Approaches](https://www.sei.cmu.edu/library/software-architecture-reconstruction-practice-needs-and-current-approaches/).
