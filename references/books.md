# Books

These references provide conceptual grounding for the playbook. They are not treated as sources of universal prescriptions. A recommendation should point to the relevant concept or pattern, not merely cite this page as a whole.

## Software Architecture in Practice

Len Bass, Paul Clements, Rick Kazman, *Software Architecture in Practice*, 3rd edition.

Useful for quality attributes, architecture evaluation and reasoning about architectural drivers.

Publisher/source: [Software Engineering Institute](https://www.sei.cmu.edu/library/software-architecture-in-practice-third-edition/). Locator: quality attributes, quality-attribute scenarios and architecture evaluation.

## Fundamentals of Software Architecture

Mark Richards, Neal Ford, *Fundamentals of Software Architecture*.

Useful for architectural characteristics, coupling/cohesion, styles and trade-offs.

Publisher/source: [O'Reilly Media](https://www.oreilly.com/library/view/fundamentals-of-software/9781492043447/). Locator: architectural characteristics, component coupling and architecture styles.

## Building Evolutionary Architectures

Neal Ford, Rebecca Parsons, Patrick Kua, Pramod Sadalage, *Building Evolutionary Architectures*, 2nd edition.

Useful for fitness functions and continuously protecting architectural characteristics.

Publisher/source: [O'Reilly Media](https://www.oreilly.com/library/view/building-evolutionary-architectures/9781492097532/). Locator: architecture fitness functions and governance.

## Patterns of Enterprise Application Architecture

Martin Fowler, *Patterns of Enterprise Application Architecture*.

Useful as a catalog model and for patterns such as Data Mapper.

Author/source: [Patterns of Enterprise Application Architecture](https://martinfowler.com/books/eaa.html). Locator: Data Mapper and the pattern-catalog form.

## A Philosophy of Software Design

John Ousterhout, *A Philosophy of Software Design*, 2nd edition.

Useful for complexity, module depth and avoiding unnecessary abstraction.

Locator: symptoms and causes of complexity, deep modules and general-purpose versus special-purpose modules.

## Working Effectively with Legacy Code

Michael Feathers, *Working Effectively with Legacy Code*.

Useful for reasoning about change boundaries and safe evolution of legacy systems.

Locator: seams, characterization tests and safe change around existing code.

## Threat Modeling: Designing for Security

Adam Shostack, *Threat Modeling: Designing for Security*.

Useful for trust boundaries, assets, threats and explicit security reasoning.

Locator: data-flow diagrams, trust boundaries and systematic threat identification.

## Designing Machine Learning Systems

Chip Huyen, *Designing Machine Learning Systems*.

Useful for data distribution, reproducibility, monitoring and the operational lifecycle of ML systems. Locator: data engineering fundamentals and reproducibility of pipelines.
